# Dane test harness
All scripts import `greatdane/tools/gd_guard.py` first: it aborts if nowon's real
GreatDANE profiles.ini/installs.ini change, and gives throwaway profile/node-data dirs.
Run with the marionette venv, e.g.
`/Volumes/Storage/build/greatdane/mn-venv/bin/python smoke.py <Dane.app/Contents/MacOS/greatdane> arm64`

media_check.py: `media_check.py <greatdane> <arm64|x86_64> [h264file,h264,cleartears,google-tears-uat,shaka-angel-one,...]`.
Run the app from a path under /Volumes or /Applications, not /tmp: from a /tmp (symlink to /private/tmp)
mount the Widevine CDM process fails to launch ("GMPServiceChild failed to launch GMP: Process has not loaded").

ids_search_check.py: `ids_search_check.py <greatdane> <arm64|x86_64> (--expected BUILDID | --buildinfo BUILDINFO-<id>.txt)`.
The expected BuildID never comes from the app itself. Checks application.ini == platform.ini == appinfo == expected, and that every child process's -parentBuildID == expected.
run_gd_prefs.py: `run_gd_prefs.py <greatdane> [arm64|x86_64] [/abs/screens_dir]`. Without an arch it runs natively. Before this change, a second argument was taken as the screens dir.
guard_negative_test.py: proves gd_guard rejects out-of-root dataDir and safe() paths and stray dirs in the source tree. Launches no browser.
gd_guard now requires every profile and node data path to be inside this run's mkdtemp roots. At exit, it fails with code 96 if a profile's dataDir is outside them, or if new dirs appeared in greatdane/, the cwd, or $HOME.
passkey_check.py: `passkey_check.py <Dane.app> <arm64|x86_64> [--static-only]`. Passkey READINESS check (PASSKEYS-PLAN.md §5). A pass is not proof that passkeys work: it only shows there are no stray restricted entitlements, the pref is on and the generic WebAuthn API exists. Static: with no Contents/embedded.provisionprofile, no Mach-O may carry com.apple.developer.web-browser.public-key-credential or com.apple.application-identifier. With a profile, only the main app may carry both (MNL79V994R.surf.dogecoin.dane), and the profile must grant them. Runtime (gd_guard throwaway profile, ABI gate; marionette.port=0 with the port read from <profile>/MarionetteActivePort and the profile path verified over Marionette; browser launched in its own session and its process group killed if it does not quit in 30s): security.webauthn.enable_macos_passkeys is true and PublicKeyCredential exists. Any non-zero browser exit, Marionette error, or process left on the throwaway profile is a FAIL (script exits 1). Test hook: GD_PASSKEY_TEST_FORCE_KILL=1 SIGKILLs the browser to prove that path fails. The runtime part makes one network request, to https://example.com/ (needed for a secure context), plus stock Firefox background traffic. Read-only on the bundle; changes no signing inputs.

sign_dane_macos_selftest.py: `python3 greatdane/tests/sign_dane_macos_selftest.py [-v]`. A self-test of greatdane/tools/sign_dane_macos.py that runs on Linux or macOS and never really signs anything. It builds fake Dane.app layouts in a temp dir, including real-style framework symlinks, and puts a MOCK `codesign` first on PATH. Cases: plan, dry-run and mock sign (the identity is never printed, `--deep` is never used, the app is signed last); refusal of non-main Mach-O inside mapped bundles (minidump-analyzer in crashreporter.app, evil.dylib in plugin-container.app, framework helpers, nested bundles); restricted entitlements without a profile; the path guard (/Volumes/Dane, " N" and "-N" variants, case variants, the /System/Volumes/Data alias, danenotarized, the GreatDANE profile dir, the /Volumes allowlist); and `check` failing on a missing hardened runtime, a wrong team, a missing timestamp, wrong helper entitlements, or a team in signing.conf that doesn't match. When build/moz.configure/update-programs.configure is present, it also checks that the configure OU equals TEAM_ID in greatdane/macos/signing.conf.

- `tippytop_default_sites_check.py`: every default.sites host has a bundled tippytop icon (run from tree root).
- `no_coin_surf_product_urls_check.py`: fail if a non-excluded `*coin.surf` product URL remains (run from tree root). Scans the whole tree with explicit excludes (evidence/, publisher fixtures, the check script). `.svg` is scanned as text. Files over 2 MB fail loudly rather than being skipped. An author-email match (`nowon@noreply.pepecoin.surf`) strips only that token and re-tests the rest of the line. Allowed leftover tokens in a full tree, also stripped per-token: `seed.dogecoin.surf`, `seed.pepecoin.surf`, and the PepeNet desktop `https://pepecoin.surf/releases` URL. The greatdane.doge tile is not a `*coin.surf` host.
- `sign_only_selftest.py`: sign-only.sh with stub tools + mock codesign (DANE_ARCH allowlist, dmg refusal, realpath owner guards, ad-hoc and Developer ID runs). No real signing.
- `no_legacy_deep_sign_check.py [--root DIR] [-v]`: round 4 (L-a). Scans every text file under greatdane/ (tests and non-.sh/.py files too; Markdown fenced blocks only) plus taskcluster/config.yml. It flags the deep flag outside a verify-only command (no sign flag in it, so a `--verify` elsewhere in a signing command does not exempt it): line continuations, `$CS --deep`, `DEEP=`/`$DEEP` flag variables, file-local variables expanded (`${F}ep`), any token containing "deep" in a codesign command, eval and `bash -c`/`sh -c` strings parsed as shell, and Python strings folded from `+`, `*`, f-strings and assigned names (`D="--deep"`, `"-"*2+"deep"`, `CS+" --deep"`). It also flags browser.entitlements.plist and legacy script names (sign-only.sh unless it is `$TREE/greatdane/tools/sign-only.sh`, including via a variable, a glob or a fake path; build-universal.sh; notarize.sh without --submit-existing). YAML is checked with or without PyYAML: `deep: true` behind anchors, aliases or tags, plain and block-scalar `run:` values as shell, and no comment can hide a hit. Markdown fenced and indented code blocks are checked (round 4c L2). There is no waiver (round 4c L1): the `nolegacy:` comment mechanism is removed, and the selftest builds its must-not-match regex at runtime instead. sign_dane_macos_selftest.py runs it on this tree (L0: PASS with 0 hits and no waivers) and on fixtures (L1-L45; L21 checks that a `nolegacy:` comment no longer waives anything).
- `locale_branding_check.py`: source-level check (no build) that `generate_ini.py` overrides `MozillaMaintenanceDescription` for every locale in all-locales and shipped-locales (fixtures for de, fr, ja, zh-CN, en-GB, ar, plus synthetic leftover/missing-key cases; official Firefox wording is left alone), and that the proposed About attribution lives in greatdane brand.ftl, is shipped to every locale via locales/jar.mn, and is wired from aboutDialog.xhtml when MOZ_OFFICIAL_BRANDING is not set.
- `wordmark_branding_check.py`: source-level check (no build) that greatdane about-wordmark.svg is a plain-text Dane wordmark (context-fill, navy #13254A fallback, transparent ground, no official Firefox path-logo), that content/jar.mn aliases firefox-wordmark.svg to it and overrides window-firefox.svg to greatdane-icon.svg, that official branding is untouched, and that WORDMARK-SOURCES.md documents the stock leftovers that were not swapped.
